# 架构决策记录

状态：Phase 0 架构已验收。整体路线变更须用户确认。

## ADR-001：Rust 中心的模块化单体

- 背景/问题：媒体任务、AI 进程与 GUI 需要共享取消、预算和持久化语义。
- 备选：单语言全包；各语言各自调度；网络微服务。
- 选择：Rust 唯一调度与数据所有者，C# 展示、Python 推理、成熟原生库计算。
- 理由：保留原生 UI 和 AI 生态，同时避免重复状态机/数据库竞争。
- 性能影响：进程通信有成本；优先小控制消息+文件引用，未测量前不引入共享内存。
- 维护/兼容：契约集中 contracts，CLI 独立；仅按真实规模拆 crate。

## ADR-002：JSON-RPC 2.0 profile 与 Schema 先行

- 背景/问题：跨语言 request_id 与 JSON-RPC id 重复、错误语义易漂移。
- 备选：自定义信封；gRPC；JSON-RPC。
- 选择：JSON-RPC id 为唯一请求标识，protocol_version/task_id 放方法 payload。
  UTF-8 JSONL 帧；C# Named Pipe、Python stdio，跨平台后端可替换。
- 理由：避免新增 RPC 栈，便于诊断并与现有标准兼容；profile 禁 batch、位置参数。
- 性能影响：JSON 仅传小消息，大文件传受控引用，1 MiB 帧上限为待测安全默认。
- 维护/兼容：Draft 2020-12 Schema 为真源；strict DTO 变更要版本协商，不能默默加字段。
  Rust/Python/C# 的实际往返一致性测试在相应模块建立时加入。

## ADR-003：字幕优先、CPU 基线与成熟原生库

- 背景/问题：低内存、少下载、低额度成本比无条件硬件加速更重要。
- 备选：所有任务先下载视频；统一 GPU/NPU；自写底层算法。
- 选择：优先字幕、按需音视频、INT8 候选、FFmpeg CLI，模型按需复用；CPU 先测。
- 性能影响：可能减少工作量，但尚无测量值；精度与速度一起评估。
- 维护/兼容：OpenVINO/QSV/FFI/共享内存只有数据证明价值时引入，CPU 可回退。

## ADR-004：受限 Codex Provider 与额度保护

- 背景/问题：用户希望使用现有 ChatGPT 登录，但内容包含不可信指令且额度有限。
- 备选：付费 API 默认；无限自动重试；直接以开发 Agent 权限总结。
- 选择：接口可替换、Mock 默认，真实调用显式限额；最小权限和证据校验通过后启用。
- 理由：不增加必需 API 消费，避免视频指令触发工具或读取凭据。
- 性能影响：分段/缓存降低重复消耗是设计意图；token/视频小时实测后再结论。
- 维护/兼容：版本/模型/参数运行前探测；隔离不足时 fail closed，不伪造成功。

## ADR-005：统一视觉与本地化资源

- 背景/问题：多模型协作可能导致页面独立配色、重复组件与 Web 风格漂移。
- 备选：各页面自主设计；WebView UI；原生资源字典。
- 选择：Avalonia 统一 tokens、组件、主题、中文资源及原生 Markdown 渲染。
- 性能影响：长列表虚拟化、不阻塞 UI；实际 RSS 与帧响应尚未测量。
- 维护/兼容：更改共享视觉先修改 DESIGN_SYSTEM，检查所有页面/主题/缩放影响。

## ADR-007：任务状态机作为首个 Rust 子任务

- 背景：Phase 01 获准按独立可验证子任务交付，本次限定任务状态机。
- 选择：先建立 core crate 的纯状态转换模块，复用 Serde 与共享 Schema 状态名称。
  内部事件与 RPC 方法分离，完整 DTO、调度和持久化在后续子任务接入。
- 规则：取消先接受时拒绝迟到结果，终态保持稳定，暂停在步骤边界确认，
  限额与重启中断状态由用户恢复。完整转换表见 [TASK_STATE](TASK_STATE.md)。
- 兼容：公共协议版本和字段不变，测试对照 Schema 枚举与已有 fixtures。
- 维护：只有 core crate 有实际行为；CLI 在有可运行入口时创建。
- 验证边界：纯状态函数测试覆盖事件顺序，数据库事务和进程取消仍需后续实测。

## ADR-008：显式事件循环的有界 Mock 调度

- 本子任务以标准库集合实现同步内存调度，复用 TaskState 转换，I/O 接入时引入 Tokio。
- 容量覆盖全部保留任务，终态显式回收，执行并发单独限制，满容量返回 Full。
- 调度器实例与每次派发均有唯一内部标识，迟到结果在状态更新前拒绝。
- 单 Provider 配额门禁通过显式恢复重新开启，Worker 标记在限额期间保留。
- 原子发布当前由独占内存操作保证，SQLite 和真实进程生命周期在后续子任务实现。
- 详细接口语义与测试边界见 [SCHEDULER](SCHEDULER.md)。

## ADR-009：进程树复用与有界异步 I/O

- 本次以 Tokio 接入真实进程与管道，ProcessSupervisor 独占 Scheduler，完成回收继续按执行票据裁决。
- 复用 process-wrap 10.0.1 的挂起创建/Job Object 与 Unix 进程组，避免手写平台进程创建层。
  windows/nix 使用依赖树中相同版本；来源、最低工具链、许可核查和限制见进程说明。
- 合作取消以 stdin EOF 为当前短生命周期进程的机制；未增加或修改 Worker 公共 RPC。
- 输入/输出队列按固定块有界，运行与清理均有期限；确认清理前保留槽位，失败时隔离。
- 不以完成端口通知作为树已退出的证明；Windows 外层 Job 查询活动数，Unix 检查进程组消失。
  外层 Job 在恢复执行前归属；保留库的启动/终止封装，不调用其树等待。正常退出也清理子孙。
- Unix 保留根进程 PID 直至完成终止信号操作。管道报错与清理确认分别记录，取消时关闭输出队列并丢弃未读数据。
- 本次只验证合成进程；真实 Worker 协议、输出语义校验、SQLite 和缓存继续按阶段实现。
- 详细语义、平台限制与验收见 [PROCESS_SUPERVISION](PROCESS_SUPERVISION.md)。

## ADR-010：SQLite 事务与恢复所有权

- Rust core 复用 rusqlite 0.43.0（MIT）与随附 SQLite，支持 MSVC 和 Linux 同一迁移序列。
- 独占应用目录内的锁文件以区分启动恢复和同一进程新建写连接。实际写入由 SQLite 事务串行裁决。
- 每次派发生成一次性票据。事务内同时提交终态、检查点、输出引用并撤销票据。
- 迁移采用在线备份以包含 WAL，事务覆盖表结构和版本号。恢复规则沿用 TaskState。
- 已有库先只读识别，再在写事务复核。备份发布等待 Windows 写穿透移动或 Unix 目录同步成功。
- 依赖来源、测试和限制见 [SQLite 任务存储](STORAGE.md)。

## ADR-011：阶段缓存内容核验与中文子串检索基线

- Rust 复用 BLAKE3 和现有 SQLite 事务、迁移备份及持久化文件发布。下游缓存键包含直接输入的键和实际内容摘要。
- 缓存键规范版本隔离旧参数编码。显式重建受保护的损坏产物时，摘要变化与受影响的任务检查点失效一起提交。
  启动清理失败可重试，任务恢复单独提交。
- 中文字面子串检索以 SQLite 内置 FTS5 trigram 配合短词扫描作后续对照基线。它在本次语料中达到完整召回，
  索引比 bigram 小一页。高频短词查询需保留 bigram 作速度对照。生产字幕索引和排序另行验收。
- 合成语料、测量口径、限制及复跑入口见[缓存与中文检索](CACHE_SEARCH.md)。

## ADR-012：单所有者的前台 Mock CLI

- 独立的 videosift-cli 使用 [Clap](https://github.com/clap-rs/clap) 解析命令，锁定 4.6.9
  （MIT 或 Apache-2.0，最低 Rust 1.85）。core 组合原有调度、执行票据、事务和缓存接口。
- 一次前台运行持有一个任务库。交互模式在已提交的 Worker 检查点通过 stdin 接受取消；
  重启时由原有存储恢复所有权，使用原任务编号显式恢复。
- stdout 的 JSONL 用于本地命令结果；后台服务、GUI 连接和跨语言 RPC 保持各自的阶段边界。
  [CLI 说明](CLI.md)列出退出码、合成输入及验收方法。
