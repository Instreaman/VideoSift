# 本地视频文件来源

Rust core 的 `local_file::validate_local_file(root, input)` 对调用方选中的一个文件执行只读校验。
成功返回 `LocalSource`，可用 `VideoSource::Local` 与现有 Bilibili 来源共用序列化入口。
成功表示普通文件非空且已读完，扩展名任意。媒体头、容器、编码、时长与可播放性留待媒体处理阶段验证。

## 路径与授权

- `root` 是调用方通过可信方式选定的绝对目录，其解析目标构成授权边界。调用方须控制该根的来源及打开时的绑定；
  请勿直接从未校验的输入截取父目录作为授权根。根下可以有多个文件，core 只处理明确传入的一个名字。
- 相对路径以该根为基准。绝对输入须能按路径组件剥离同一根前缀，建议沿用根的拼写。
  空路径、`..`、越出根的绝对路径均拒绝。目录和带目录后缀的普通文件输入均不能作为视频来源。
- 拒绝符号链接（含指向根内的链接和断链），读取前复核最终文件句柄的类型。普通文件硬链接按其内容处理。
- Linux 对根下直接子文件使用根句柄和禁止跟随链接的打开方式。对于嵌套文件，预检后回到原始根句柄，
  用一次 `openat2(RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS)` 解析完整相对路径并打开。约束在取得可读句柄时成立。
  若中间目录已移走、原名缺失，打开失败；若原名变成链接，即使指向根内也会被拒绝。
  若该位置已有新的合法普通文件，校验对象以最终在根下打开的文件为准。
- Linux 内核缺少 `openat2` 或拒绝所需解析标志时，嵌套打开返回 `Access(Unsupported)`；
  系统策略返回权限错误时保留对应错误类别。这些情况都不退回逐级打开。其他 Unix 目前只支持根下直接子文件，
  嵌套输入返回 `Access(Unsupported)`。调用方可另行明确授权文件的直接父目录。
- Windows 对每个中间目录执行禁止跟随链接的打开，随后从实际取得的目录句柄读取属性，
  发现 `FILE_ATTRIBUTE_REPARSE_POINT` 即返回 `Link`，在解析下一级前结束。最终文件也检查句柄属性。
- Windows 授权根使用本地盘符路径；输入不接受 UNC、盘符相对路径和 NTFS 备用数据流。部署方负责选择本地存储，
  此接口无法判断某个挂载目录或映射盘的物理存储位置。

## 标识、错误与隐私

`source_id` 是从打开的文件句柄顺序读取字节所得的 BLAKE3 摘要，以 64 个小写十六进制字符表示。
字节相同的文件在改名、移动、复制或切换机器后得到相同标识。写入不同字节会改变摘要。
标识不包含文件名、目录、时间戳或大小；持有候选内容的人可以比较摘要判断内容是否相同。
序列化固定包含 `kind: "local"`、`source_id` 和 `part_id: null`。见[共享样例](../contracts/examples/valid.json)。

读取以打开时记录的长度为上限，读取前后核对同一句柄的长度与修改时间。短读或可观测变更返回 `Changed`。
该检查不提供不可变快照，调用方应提供稳定文件，并在后续需要使用文件时重新校验。
校验耗时随文件字节数线性增长，读取使用有界缓冲，未实测视频吞吐。

| 结果 | 调用方可采取的操作 |
| --- | --- |
| `InvalidPath` | 重新指定授权根和文件路径。 |
| `NotFound` | 检查文件及父目录是否存在。 |
| `Directory` / `NotRegular` | 选择普通文件。设备、套接字等不作为输入。 |
| `Link` | 在授权根下直接选择目标文件。 |
| `Empty` / `Changed` | 等待写入完成后重新校验。 |
| `Access(ErrorKind)` | 按系统错误类别处理权限、共享冲突或其他 I/O 故障。 |

错误只携带分类，不附原始路径。此入口不枚举目录、不产生缓存或日志、不调用外部程序。
Linux 回归将预检和最终打开分开，在两者之间移动临时子目录或改变原名的链接状态；断言打开阶段即返回错误。
Windows 保留真实 junction 输入测试，另用普通目录通过预检，再由测试提供真实 junction 本体的句柄，
验证打开后的属性检查可以独立拒绝它。后者控制了返回的句柄，未制造真实并发替换或安装其他重解析点驱动。
